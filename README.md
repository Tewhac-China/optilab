## 二、物理模型

严格按实验讲义实现两步光学过程。

### 1 输入面

```
h(x, y) = A(x, y) · [ f(x + a, y) + g(x − a, y) ]
```

- `f` 待识别目标、`g` 参考目标，中心分别位于输入面 `∓a` 处
- `A(x,y)` 为激光照明包络（高斯光束，可调非均匀度）
- 另有输入面圆形光阑限制口径

### 2 谱面（第一步）

```
S(u, v) = |FT{h}|²                            平方律记录 → 联合功率谱 JPS
```

### 3 输出面（第二步，相关读出）

```
o(ξ, η) = FT{S}
        = (f ⋆ f) + (g ⋆ g) + (f ⋆ g)(ξ − 2a) + (g ⋆ f)(ξ + 2a)
          └── 零级项 ──┘   └──── 一级互相关项 ────┘
```

互相关峰位于

```
ξ = ±2a · (f₂ / f₁)
```

### 标定关系

| 量 | 表达式 | 默认值 |
|---|---|---|
| 输入面尺寸 | `L = N·dx` | 10.24 mm |
| 频率采样 | `du = 1/(N·dx)` | 97.66 m⁻¹ |
| 谱面采样 | `dξ_s = λf₁·du` | 9.270 µm |
| 输出面采样 | `dξ_o = dx·f₂/f₁` | 10.00 µm |
| 杨氏条纹周期 | `Λ = λf₁/(2a)` | 29.66 µm |
| 互相关峰位 | `ξ = ±2a·f₂/f₁` | ±3.200 mm |

### 已实现的现代方法

- **二进制 JTC**：JPS 阈值化，显著锐化相关峰
- **相位化 JTC**：JPS 仅保留单位幅值
- **径向高通**：抑制零级自相关，提升一级项对比度
- **有限量化位数**：模拟记录器件的量化噪声

## 三、技术实现

### 3.1 零依赖 WebGL2

不使用 Three.js 等框架，全部手写渲染管线。这样做的关键收益：
**GPU-FFT 的计算纹理可以被 3D 场景直接采样，无需跨上下文拷贝或 readPixels 回读。**

### 3.2 GPU 复数二维 FFT

- 分解：`2D DFT = 行变换 → 转置 → 列变换 → 转置`
- **蝶形配对**：第一次变换用 DIF（自然序入 / 位反转序出），
  第二次变换用 DIT（位反转序入 / 自然序出）——
  两者恰好首尾相接，**无需任何额外的位反转重排 pass**
- twiddle 因子预计算为 1D 纹理，避免逐像素三角函数
- 数据格式 RGBA32F，`(R,G) = (Re, Im)`
- 默认 1024²，22 个 pass 完成一次二维变换

### 3.3 渲染管线

```
天空(逐像素方向重建)
  → 方向光阴影贴图 (R32F 线性深度 + 3×3 PCF)
  → 程序化网格地面
  → PBR 主材质 (GGX + Smith + Schlick，3 光源 + 程序化环境光箱)
       · 贴花通道 uDecal（激光警示标签 / 铭牌 / 镜筒刻字 / 刻度）
       · 粗糙度-磨损微扰（滚花与拉丝表面的高频细节）
  → 屏幕材质 (SLM / CMOS / 输出屏，含像素栅格、玻璃盖板反射、屏边压暗)
  → 加性体积光束（相机朝向的双片 ribbon，高斯径向包络 + 轴向包络）
  → 透明材质
  → 线框
  → SSAO（半分辨率，深度纹理 + 两次盒式模糊）
  → Bloom (亮度提取 + 5 级降采样/上采样)
  → ACES tonemap + FXAA + 色差 + 暗角 + 颗粒
```

- **光照方向约定**：`lights[i].dir` 存的是光的**传播方向**（与阴影相机 `eye = target − dir·d` 一致），
  着色时取 `L = normalize(−dir)`。早期版本直接拿 `dir` 当「指向光源」用，受光面被判成背面跳过，
  整个场景几乎只剩环境光——画面发闷、缺立体感、金属像塑料，根因就在这里。
- 环境镜面项按粗糙度衰减 `(1 − rough·0.92)`：哑光台面（rough 0.82）在掠射角不再泛出一片灰雾
- 光学平台孔阵：1680 个销孔合并为单个 mesh，一次 draw call
- 全部几何程序化生成（透镜为真实双凸球面，含边缘柱面）
- 器件外形按真实零件建模：滚花旋钮用数值法线生成真实滚花纹路，
  线缆用 Catmull-Rom + 平行传输标架扫掠，铭牌用弧面壳体（arcShell）贴合圆柱面

### 3.5 实测性能与优化

在 AMD Radeon 集显（ANGLE / D3D11）上：

| 指标 | 数值 |
|---|---|
| 渲染帧率 | ~120 fps |
| 每帧耗时 | ~1.8 ms |
| draw call | 336–357 |
| 三角形 | 168,700 |
| 单次完整光学求解 | ~240–290 ms |

> 无 GPU 的 CI 环境（SwiftShader 软件光栅）下为 6–7 fps / 求解 ~1 s，
> 该数值仅用于回归测试，不代表真实设备表现。

本轮的四处性能改动（SwiftShader 下 6 → 13 fps，真实 GPU 同比例受益）：

| 改动 | 收益 |
|---|---|
| **阴影贴图缓存**：平行光与场景都是静态的，只有器件移动 / 光阑改口径时才重画（`invalidateShadow()`） | 省掉每帧一整遍不透明几何（≈400 draw call） |
| **`preserveDrawingBuffer: false`**：截图在同一帧 rAF 回调里 `toDataURL`，不再强制每帧复制后备缓冲 | 省掉每帧一次全分辨率拷贝 |
| **自适应渲染比例**：帧时间 >26 ms 连续偏高就降到 0.62–1.0 倍，恢复后自动升回（`_adaptQuality`） | 高 DPI / 弱 GPU 上优先保帧率 |
| 阴影贴图 2048→1536、bloom 5→4 级 | 填充率与带宽 |

> 阴影缓存的坑：`_buildTargets()` 重建渲染目标（窗口尺寸变化、自适应分辨率切换）时
> 会 new 一张空的阴影贴图，内容是 0 = 最近深度。如果不标记为脏，整场都会被判成
> "在阴影里"——**主光直接消失，画面只剩环境光**。这是"照明光有时候没了"的根因。
> 现在 `_buildTargets` 末尾置 `_shadowDirty = true`；阴影相机也改成钉在台面中心
> （原来跟着相机 target 跑，平移后阴影锥会离开场景）。

光学求解仅在参数变化时触发，并做节流（>110 ms 间隔）。

**求解侧的读回优化（本轮）**：一次完整求解原本有 4 次 `reduce`（512² 浮点回读）+ 1 次
1024×1 整行回读，SwiftShader 下 4 次 `reduce` 占 225 ms、整行占 106 ms，合计约 80% 的耗时。
现在：

| 改动 | 效果（SwiftShader） |
|---|---|
| 噪声 / 量化 / 谱面处理合并成一条 pass 链，只在末尾回读一次 | 完整解 −56～170 ms |
| Parseval 统计移到离焦滤波之前，复用同一次回读 | 少一次回读，读数也不再随离焦「失真」 |
| 输入场常驻 `texIn`：图案/光阑/照明不变时用 GPU 拷贝代替 4 MB `texSubImage2D` | 移动透镜类操作省 40–200 ms |
| 上传缓冲复用（16 MB + 8 MB 半浮点，原来每帧新分配） | 消除拖拽时的 GC 抖动 |
| **预览解**：拖动元件 / 拖滑块时 `solve(preview)` 只做 FFT 与贴图，完全不回读 | 430 ms → 拖动期间单帧 <5 ms（GPU 异步），松手后补一次完整解 |

实测：完整解 656 ms → 预览解 1 ms（同步返回），拖动 20 步总耗时从 4.1 s 降到 2.3 s
（剩余时间是 SwiftShader 的 GPU 光栅本身，不是读回）。

### 3.6 光路与讲义逐件对照

讲义第 5 章给出的仪器顺序是：

```
HeNe → 空间滤波器(物镜+针孔) → 准直透镜 → 起偏器 P1 → SLM → 检偏器 P2
     → 傅里叶透镜 L → CMOS(谱面)   ──第二步──   SLM 回放 JPS → L → CMOS(相关峰)
```

本仿真按这条链路逐件建模，编号与「光路元件」列表一致：

| # | 器件 | 讲义中的角色 | 台面 x |
|---|---|---|---|
| ① | HeNe 激光器 | 632.8 nm 单色光源 | −20 mm |
| ② | 可变光阑 | 高度基准（近场/远场都通过） | 155 mm |
| ③ | 空间滤波器 | 物镜 + 针孔，滤除高阶模 | 260 mm |
| ④ | 准直透镜 f=150 | 针孔置于前焦面 → 平面波 | 439 mm |
| ⑤ | 照明光阑 | 限制照明口径 | 550 mm |
| ⑥ | **起偏器 P1** | 为液晶提供线偏振入射 | 600 mm |
| ⑦ | 输入面 SLM | 显示 f(x−a)+g(x+a) | 680 mm |
| ⑧ | **检偏器 P2** | 与 P1 正交，把偏振调制转为强度调制 | 722 mm |
| ⑨ | 傅里叶透镜 L₁ | 第一次 FT → 谱面 | 830 mm |
| ⑩ | CMOS | 平方律记录 JPS | 980 mm |
| ⑪ | 读出 SLM₂ | 第二步回放 JPS | 1130 mm |
| ⑫ | 傅里叶透镜 L₂ | 第二次 FT → 相关面 | 1280 mm |
| ⑬ | 输出面 | 零级 + ±2a 互相关峰 | 1430 mm |

**两点必须说清**（也是与讲义不完全相同的地方）：

1. **两步法摊平成一条线**：真实装置里第二步是把同一片 SLM 改显示 JPS、同一片傅里叶透镜
   再做一次变换（讲义图 3 也是画成上下两条光路）。为了在一条台面上看得见"两次变换"，
   这里把第二步的 SLM/透镜/屏单独摆成 ⑪⑫⑬ 三件，物理上完全等价（4f 的等比缩放、
   峰位 ξ=±2a·f₂/f₁ 都不变），界面上标注为「读出 SLM₂（第二步）」。
2. **焦距取 150 mm 而非讲义标注的 ≈400 mm**：400 mm 的 4f 半程就是 800 mm，
   两步需要 1.6 m 以上，台面（1.8 m）放不下还留不出调整余量。模型里 f₁、f₂ 可调
   （光学参数面板），标定关系 dS=λf₁/(Ndx)、dO=dx·f₂/f₁ 与 f 显式相关，
   改回 400 mm 物理量会自动重算，只是器件间距需要相应拉开。

> 建模踩坑记录 ②：`geo(key, factory)` 的缓存键必须包含 factory 里用到的**所有可变参数**。
> `irisFace` / `irisRim` / `irisKnurl` 的键曾经不带孔径，结果拖光阑滑块时只有背后的喉部变了，
> 正面挡板（用户看到的「孔」）永远停在初始半径 —— 表现就是「调了没反应」。
> 现在键统一为 `名字_孔径签名`。
>
> 建模踩坑记录 ①：`knurledGrip` 的四边形绕序曾经写反 —— 外表面被背面剔除，
> 看到的是筒内壁，于是每个滚花环都变成「一片薄薄的弧形壳」浮在零件旁边。
> 凡是「看起来像一片壳 / 一个洞」的圆环件，先查绕序。
> 同理：分两件建模的「手柄 + 旋钮」很容易对不上，能合并成一根车削件就合并。

几何全部由 `geometry.js` 的参数化基元生成：数值法线参数曲面、车削（lathe）、
圆角盒（roundedBox，6 面 + 12 边柱 + 8 球角）、数值法线滚花（knurledGrip）、
Catmull-Rom 扫掠管（tubePath）、弧面壳体（arcShell，用于圆柱面贴花）。
绕序由面法线与顶点法线的一致性自动校正（`quadA` / `triA`），不会出现翻面黑洞。

### 3.9 光束传播模型（3D 光斑形状）

3D 箱庭中的激光束不再是固定半径的装饰几何，而是由 `optics.js` 的
`BEAM_MODEL.beamModel()` 按真实链路逐段计算 1/e² 半径包络：

| 区段 | 物理规则 |
|---|---|
| HeNe 出光口 → 光阑① | 高斯自由传播 w(z)=√(w₀²+(λz/πw₀)²)，w₀=1.6 mm |
| 物镜聚焦 → 针孔 | 衍射焦斑 w₀=0.61λ/NA′（NA′=NA/M=0.02 → ⌀39 µm），z_R≈1.8 mm |
| 针孔 → 准直透镜 | 基模点源远场锥，半角 θ=NA′ |
| 准直后平行光 | w = f_准直·θ，受透镜通光口径截断；拖动准直镜实时重算 |
| 光阑② / 输入面 | 硬光阑 min() 截断；照明 = 光束与高斯包络 σ·L/2 的交集 |
| 输入面 → L₁ | 衍射发散 θ_d=λ/πw_in |
| L₁ → 谱面 | JPS 扩展包络 R=0.45·N·λf₁/L；CMOS 离焦叠加模糊圆 r·\|Δ\|/f₁（调焦可见） |
| 谱面 → SLM₂ | 电子学读出链路（冷色光段），按 4f 比 f₂/f₁ 缩放 |
| SLM₂ → L₂ → 输出面 | 第二次 FT，输出照明 R=0.45·N·dx·f₂/f₁，互相关峰落于 ±2a·f₂/f₁ |

**画出来的光柱宽度 = 真实 1/e² 光斑直径**。这里踩过三个坑，都修了：

| 坑 | 后果 | 修法 |
|---|---|---|
| `uSpread = 4.2`，光带画成 4.2 倍束径 | 宽度是假的，怎么调都看不出变化 | 改 1.55，只留一点外晕余量 |
| 亮度 ∝ 1/w² | 细腰段削顶成一根白线 | 改 ∝1/w，压缩到 0.42–1.55 |
| **纯加法混合** | 两片光带叠加，中心瞬间饱和成白色，"线"取代了"柱" | 改 alpha 混合，alpha 封顶 0.90，径向渐变保留 → 光柱有轮廓 |

另外 `wIn` 原来与 `σL/2` 取 min，而 σL/2 就是光束自身宽度，等于把光阑的作用
整个吃掉；去掉这个 min，并让照明口径按 `kIllum = w_in / 3.4 mm` 传递到谱面与
相关面（光阑收一半，整条下游光斑都收一半）。实测：光阑 11 → 1.5 mm，
输入面光斑 6.72 → 3.39 mm，输出面 9.11 → 4.59 mm。

**光柱半径受每个器件的通光孔径约束**（`world.beamApertures()`）：

| 器件 | 通光半径 | 说明 |
|---|---|---|
| HeNe 出光口 | 3.0 mm | 原生束腰 1.6 mm，出光口略大 |
| 光阑 ① / ② | 叶片喉部半径（② 随滑块变化） | 光束在这里被真正截断 |
| 准直镜 / L₁ / L₂ | 11.3 mm | 镜筒端面内孔 |
| 起偏 / 检偏 | 20.6 mm | 偏振片压圈内孔 |
| SLM 窗口 | 24.0 mm | 显示区半幅 |
| CMOS 靶面 | 10.0 mm | 靶面半幅 |

绘制时每个节点先乘显示加粗倍率，再夹到该平面的通光半径；被夹住的平面在前后各插一个
节点（±1.8 mm），让光柱在孔口**齐茬收住**，而不是从几十毫米外就慢慢收成锥形（那是聚焦，
不是截断）。所以光阑一关，孔口之后的光柱立刻变成孔径大小，且任何视角下都不会「穿过」金属环。

实测（光阑半径 → 光阑平面光斑 ⌀）：4.0 mm → 6.33 mm（光束自己更细，孔径不限制）；
2.2 mm → 4.4 mm（被孔径截断）；1.5 mm → 3.0 mm。

**默认光阑收到 4.0 mm**：正好包住 6.3 mm 的照明光柱（讲义步骤 5「调整光阑大小使激光束
完全照射目标且不超出」）。之前默认开到 11 mm，孔是光柱的 3.5 倍，看起来「光柱跟孔完全不搭」。

**读数**：悬停任意器件显示「光斑 ⌀6.33 mm / 孔 ⌀8.0 mm」，被截断时改为
「⚠ 已被 ⌀4.4 孔径截断」；`光斑` 开关打开后，每个光学平面画一圈 1 px 截面圆
（顶到孔径时转成琥珀色），并给光阑与三个镜筒画一圈暗色孔径环。

**光柱加粗显示**：真实光斑只有 6–9 mm，看全台面时不到 3 px，无论几何多准都只会是一根细线。
视图工具条上的「光柱 ×2」按钮可在 ×1 / ×2 / ×3 之间切换（只影响显示，物理量不变），
悬停提示的 ⌀ 与左下角 w(x) 曲线始终是真实值。加粗后宽度仍受孔径夹紧，所以不会穿墙。

**光斑截面环**：每个光学平面上画一圈 1 px 线段圆（半径 = 该处 1/e² 半径）+ 十字刻度，
全部合并成一个 draw call。用线段而不是细圆环，是因为圆环在台面尺度只有 0.1 px、
根本看不见；线段恒定 1 px，缩到看全台面也能读出光斑大小，拉近时它就是贴着光束的
真实尺寸的圆。

λ、σ、f₁/f₂、dx、N、光阑口径、针孔偏心、准直镜位置都会触发光束重建；
视口左下遥测条实时显示滤波束腰、准直口径、衍射半角与谱面艾里斑。

| 43 | 顶住时只有屏幕顶部一条 toast，离手底下的元件很远 | 反馈位置错 | 指针旁即时提示「⛔ 顶到「X」· 松手后可先把它挪开」+ 选中框变琥珀色；导轨尽头另给「已到导轨尽头」 |
| 44 | 拖动时每帧重建光束两次、w(x) 图重绘两次 | `movePartX` 和 `doSolve` 各重建一次 | 用「光阑口径 + 针孔透过率」签名判断，40 帧内重建次数 78 → 40 |
| 45 | 弱 GPU 上拖动掉到 3 fps | 交互时仍按常态分辨率渲染 | 拖动期间允许自适应比例再降一档（0.62 → 0.45），**只在帧时间 >45 ms 时**触发，松手自动升回；SwiftShader 拖动 3.6 → 6.8 fps，真机不受影响 |
| 46 | f₁/f₂ 滑块下限略低于台面可达范围（80/50 → 实际 82.3/59.2） | 换了真实伸出量后极限变了 | 滑块收到 85 / 60 |

**第六轮（「完全拖不动」：把拖动链路从头到尾重做）**

上一轮把「间隙」当铁律（3 mm 硬约束），结果是一串器件互相顶住后，每件的可用区间只剩 0.2 mm；
再加上伸出量算错，整条导轨会被锁死 —— 用户看到的就是「完全移不动」，而且没有任何办法解开
（邻居同样被夹死）。这一轮把拖动链路整条重写：

| # | 问题（现象） | 根因 | 修复 |
|---|---|---|---|
| 47 | **器件完全拖不动**：拖到邻居旁边之后就再也移不开，邻居也拖不动 | 夹紧区间用「3 mm 硬间隙 + 对称半宽」；一旦挤紧，`lo > hi` 被折叠成零宽区间 → 永久锁死 | 硬约束只保留「不重叠」（0.8 mm）；区间永不退化成零宽（压住时留 ±2 mm 挣扎空间） |
| 48 | 伸出量算错：每件都被算成 ±180 mm | 用 `n.world` 量包围盒 —— `movePartX` 只刷新器件自身矩阵，子节点的 world 要等下一次渲染才更新，量出来整体偏移一个位移量，还被缓存下来 | 改为「相对器件原点」的局部矩阵累乘（`M4.mul(parent, n.matrix)`），与渲染时机无关；量出的值也已在器件坐标系里，不能再减 `root.pos` |
| 49 | 拖到顶住时**推不动邻居**（真实导轨上镜架会互相顶着走） | 夹紧把「下一件」当静态障碍 | 新增 `_moveChain()`：沿拖动方向做一维接触求解，位移超过间隙才带动下一件；从链尾往链头夹紧 |
| 50 | 推送时整串器件**突然倒退 30–120 mm**并互相压住 | 链条里各件间隙不同，按「夹紧到上限」会把几十毫米的空隙一次性收掉 | 推送只允许向前（`u < u(current)` 时取当前值），绝不把器件往回拉 |
| 51 | 链条在任意位置**乱断**（推一半就不动了） | 间隙公式把 `near`/`far` 用反（拿 t 的右边缘去比 prev 的左边缘） | 间隙 = 「后一件背向拖动方向的边」到「前一件迎向拖动方向的边」 |
| 52 | 旧存档（间隙更小的旧版本摆的）恢复后**互相压住、拖不动** | 恢复时不做整理 | 新增 `_sanitizeLayout()`：启动 / 重置后顺次推开到 1.2 mm 并收进台面 |
| 53 | 导轨两端写死 −0.16 / 1.56 m，激光器管身探出台面外 → 「往左拖」被判成越界 | 常量与台面几何脱节 | 新增 `_rail()`，由 `CFG.TABLE_CX/TABLE_L` 反推（−0.198 / 1.598） |
| 54 | 点 P₂ 正中央，动起来的却是后面的 L₁ | 射线穿过 P₂ 的通光孔打到 L₁ 的镜架上，`pickSoft` 只在「什么都没命中」时才兜底 | 命中件的**光轴离射线很远**（>12 mm）而另一条光轴正对点击点（<4 mm）时，以后者为准 |
| 55 | 拖动时器件**跟不上手**：拖 100 px 只走 90 px | 透视下「1 px = 多少 mm」随位置变化，按起点尺度线性换算必然偏小 | 对投影式做牛顿迭代（每步用该处导数），实测 100 px → 98.7 px（残差为网格吸附） |
| 56 | 顶住后回拖要「先退回顶住那一刻的位置」才跟手 | 顶住时基准未重锚 | 夹紧分支里 `grab.partX = 实际位置 − 本帧位移`，实测顶住后回拖 60 px 立即走 82 mm |

**第十轮（同一块谱面，两种样子 —— 显示链对齐）**

「3D 屏上有噪点、点开大图却干干净净」。查下去是三条各自独立的偏差叠在一起：

| # | 问题 | 根因 | 修复 |
|---|---|---|---|
| 71 | **大图 / 右栏小图没有噪点，3D 屏却有** | 2D 视图画的是 `sArr`，而默认模式（原始 JPS）下它只在 `jpsMode ≠ 0` 时才回读 —— 拿到的是**加噪之前**的统计；3D 屏用的 `dispJps` 纹理却是加噪后的 | 谱面统计一律回读「屏上那一张」（含读出噪声 / 量化 / 谱面处理）。只多一次回读，且只在完整求解时发生，拖动预览仍零回读 |
| 72 | 同一块谱面，屏上糊成一片青噪点、大图却是黑的 | 屏用对数底 **1e-6**，2D 用 **0.004** —— 0.25% 的读出噪声在 1e-6 的底上被抬到 0.5（糊满全屏），在 0.004 的底上又被压成 0（全黑） | 抽出共享常量 `JPS_LOG_FLOOR = 1e-4`：噪声落在 0.30（可见细散斑）、一级条纹 0.45–0.6、直流 1.0，三层都分得开 |
| 73 | 谱面屏的动态范围被「平方」了两次 | `S` 已经是 `|H|²/N²`，显示 pass 却用 `mode:0`（取 `|c|²`）再平方一次 | 改 `mode:1`（取 `|c|`），与 2D 视图的归一化一致 |
| 74 | `drawField` 传 `floor: 0` 会被悄悄换成 0.004 | `opts.floor \|\| 0.004` 把「0 = 线性」当成了「没传」 | 改成 `opts.floor === undefined ? 0.004 : ...`，并补 `opts.gain`（屏幕的 ×0.82 能复现） |

> 现在 3D 悬浮屏、右栏「光场视图」、大图、导出的 PNG 用的是**同一份数据 + 同一套色调映射**；
> 屏上略亮一点是 3D 光照（环境光 + 玻璃反射 + bloom）造成的，属于材质，不属于数据。

| 区域 | 内容 |
|---|---|

**三个悬浮光场面板**位于输入面 / 谱面 / 输出面上方，实时显示对应光场；面板由台面上的立杆 + 横臂 + 球头支撑，随视角 billboard 转向相机。
**点击任意一块屏**即可打开对应光场的大图（缩放 / 复制 / 保存 / 点空白退出），也可按 `F` 或点右栏「展开」。

**光束半径剖面 w(x)** 固定在舞台左下角：横轴是台面位置、纵轴是该处 1/e² 光斑半径，
竖线标出 11 个元件的平面（带编号），曲线随任何元件移动 / 光阑开合 / 准直变化实时重绘。
把鼠标悬停到元件上，提示里也会给出该平面的光斑直径（⌀ mm）。

### 交互

- 左键拖动：**抓住场景**旋转（场景跟着指针走，前后半球一致）；命中元件时改为沿导轨拖动该元件
- **器件之间不能互相穿过**：拖动时按各自的轴向半尺寸夹在左右邻居之间（留 4 mm），顶住时提示
  「顶到「CMOS 谱面探测器」了，先把它挪开」——和真实导轨上两块镜架顶到一起的手感一致
- 针孔盘：**点哪儿孔就移到哪儿**（不是只能拖），指示点与指针 1:1 对应；方向键 1 µm 微调（Shift 5 µm）
- 右键 / Shift+拖动：平移；滚轮：缩放
- 单击元件：选中并显示参数
- 拖动吸附：默认 **0.25 mm** 刻度（对应导轨标尺），按住 `Shift` 进入 **0.02 mm** 精调；
  引导模式下靠近理论位置（±2 mm）会自动吸附到理论值
- `W A S D` 漫游，`Q E` 升降，`Shift` 加速
- `1 / 2 / 3` 切换箱庭 / 光轴 / 屏面视角
- `R` 复位视角，`B` 光束显隐，`G` 悬浮面板显隐，`F` 全屏光场
- `Ctrl+Z` / `Ctrl+Shift+Z` **撤销 / 重做**（元件位置、光学参数、硬件状态、故障一并回退）
- `Tab` 依次选中元件，`Delete` 把选中元件放回理论位置
- `← → ↑ ↓` 针孔 1 µm 微调（`Shift` 5 µm）
- `P` 保存画面，`Ctrl+E` 导出实验记录（JSON：参数 / 硬件状态 / 元件位置 / 全部判据 / 峰位）
- `光斑` 按钮：显示 / 隐藏各元件之间自由空间里的光束截面圆（半径 = 该处 1/e² 光斑半径）
- `Ctrl+Enter` 重新求解，`?` 操作说明

### 目标图案选择

「光场视图」面板内的 f / g 缩略条显示当前待识别与参考目标，点「更换…」打开选择器：
20 种目标（汉字 / 字母 / 数字 / 几何图形 / 频谱类）以 5×4 大图铺开，顶部切换写入 f 还是 g 槽位，
底部可互换或随机。选中即生效，弹窗不关闭，方便连续对比。

> 图案网格独占 239 px 会把「光场视图」挤成 0 高（旧版本就是这样，整块面板不可见）。

## 六、学生的操作如何进入计算（真实错误 → 真实后果）

这一层的设计目标是：**任何典型操作失误都必须在结果里有可观测的物理后果**，
而不是只弹一句提示。全部通道都由真实的几何/光学量驱动：

| 操作 | 进入计算的物理量 | 后果 |
|---|---|---|
| 针孔偏心 δ | 透过率 T/T₀ = exp(−2δ²/w₀²)，w₀ = 0.61λ/NA′（焦斑 ≈19 µm）；同时偏心球面波使照明横移 θ·L，θ = δ/f_c | T 掉、照明偏心、记录信噪比 ∝ φ² 崩塌 → 峰被噪声淹没（实测 δ=10 µm → T 53 %、SNR 111；δ=20 µm → T 11 %、SNR 5） |
| 准直镜未到位 δ | 球面波照明 ⇒ 等效谱面离焦 Δ ≈ δ·(f₁/f_c)² | 与「CMOS 离焦」同一物理链条，条纹对比度塌陷（实测 Δ=25 mm → V 0.05） |
| CMOS / 输出屏离焦 Δ | 模糊圆 r_b = r_E·\|Δ\|/f，高斯等效 σ_ξ = r_b/2，频域窗 σ_rr = dx/(π·σ_ξ) | 条纹被抹平、相关峰展宽直至消失（实测 Δ=30 mm → FWHM 2.2 mm） |
| 照明光阑②通光半径 | 直接换算为输入面口径，真的截断目标（统计被挡能量比例） | 截断 <5 % 可接受；φ3.2 mm 时挡掉 46 %，PSR 反常升高（目标轮廓被切） |
| 半间距 a / 目标尺寸 w | w ≥ 2a 时一级项与零级重叠 | 峰位读到 0.54 mm（错位）→ 判据判定「无有效峰」 |
| f ≢ g | 互相关项本身变弱 | 峰消失但仍**有**条纹（V≈0.6），判决为「不相关 ✓」——这是物理，不是错误 |
| 光源/针孔造成的通量 φ | 探测器读出噪声 ∝ 1/φ²（零均值、确定性，同参数可重复） | SNR 下降 → 条纹被噪声淹没 |

### 质量判据（识别结果面板）

`条纹对比度 V`、`针孔透过率`、`一级/零级分离度 2a:w`、`记录信噪比`、
`照明均匀度`、`光阑截断`。另外分析器给出**有效性判据**：

```
valid = PSR_strict > 2 AND 位置偏差 < 6% AND V > 0.15 AND SNR > 60
```

不满足时判决显示「无有效相关峰」并列出未达标项——**避免把噪声尖峰
显示成一个看起来还很漂亮的相关峰**（这正是本次优化前的问题）。

### 条纹对比度 V 的测量方法（踩过的坑）

必须在**全分辨率**谱面的一行上测（单行 `readPixels`），因为：
1. M=N/2 的降采样读回里条纹周期只剩 1.6 px，越过 Nyquist ⇒ 条纹信息必然丢失；
2. 不能用整行 DFT 的单 bin 幅度：条纹项在谱面上是宽带（取决于目标细节）；
3. 不能用局部直流归一：大离焦时局部直流先被滤掉，商会被噪声放大（实测出现 V 反而上升）；
4. 不能用加噪后的谱面：确定性噪声的频谱结构会被误判成条纹。

最终实现：η=0 行 + 已知条纹 bin k_f 的局部正交解调（汉宁窗），
用**整行均值**归一。实测随离焦单调塌陷，对焦时 V≈0.9。
